## Documentation Rule

The repository separates:

- **EXPLORED** — possibilities and research.
- **DECIDED** — explicit decisions.
- **IMPLEMENTED** — actual code and working behavior.

A feature in the universe is not automatically an MVP feature. The MVP Contract controls implementation scope. The Validation Plan controls whether claims can be called validated.

## Review Rule

Every time-sensitive competitor, model, platform or competition claim must be rechecked before submission.

### Important scope correction

The current product documents describe **source-grounded human knowledge transmission**, while the research documents explicitly reopen the product search around **state → action → outcome**, first divergence, recovery, intervention verification and related phenomena.

Until experiments validate a direction, the product thesis and MVP contract should be treated as **working hypotheses**, not implementation instructions.
