# Track A Replay Fixtures

Use replay fixtures to validate Track A without live model calls or Track B implementation.

A fixture should make the expected chain explicit:

`source → extracted knowledge → claim → EvidenceRef → lesson/practice output`

For each case, record expected provenance and known uncertainty. Keep real expert media outside git unless an approved storage path is established.

Starter case:

`case-001/README.md` defines the expected fixture shape without inventing a domain or skill.
