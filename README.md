## Current thesis

Anveshan is exploring an AI-powered system for **capturing, grounding, transmitting, verifying, and evolving living human knowledge**.

The current product thesis is:

> **Human knowledge often exists inside people—especially tacit, embodied, local, cultural, practical, and experiential knowledge—and can disappear when transmission between people breaks. Anveshan helps make the observable parts of that knowledge explicit, source-grounded, teachable, practiceable, verifiable, and traceable across people and generations.**

### Core loop

**DEMONSTRATE → UNDERSTAND → GROUND → TEACH → PRACTICE → VERIFY → EVOLVE**

### Current product principle

**The product outcome is transmission, not preservation.**

Preservation is an important consequence of recording and structuring knowledge, but Anveshan should not be reduced to an archive, memoir generator, family-tree product, oral-history recorder, or generic AI tutor.

## Current conceptual architecture

1. **Capture** — conversations, demonstrations, video, audio, images, documents, artifacts, context.
2. **Understand** — multimodal AI extracts speech, actions, objects, sequences, conditions, cues, context, and relationships.
3. **Ground** — claims remain connected to original recordings, timestamps, people, locations, languages, and evidence.
4. **Represent** — knowledge is modeled as interconnected entities, claims, evidence, variants, and lineage.
5. **Teach** — extracted knowledge becomes adaptive learning and apprenticeship experiences.
6. **Practice** — learners attempt the skill or task.
7. **Verify** — Anveshan compares observable learner behavior/results with source demonstrations and provides evidence-based feedback.
8. **Transmit** — successful learning and adaptation become part of the knowledge lineage.
9. **Evolve** — variants, disagreements, adaptations, and new evidence are preserved rather than flattened into one supposedly universal answer.

## Current AI hypothesis

A small number of logical AI components are more useful than a large collection of superficial agents:

### Knowledge Agent
Capture → extract → structure → retrieve.

### Evidence Agent
Ground → verify → cite → detect uncertainty and contradiction.

### Transmission Agent
Teach → create practice → evaluate attempts → provide feedback → update lineage.

Deterministic ingestion, indexing, storage, security, permissions, and evaluation infrastructure should remain separate from agentic reasoning where possible.

## Current proof strategy

The first prototype should not attempt to implement the complete feature universe.

The strongest validation shape is:

> **one real expert + one bounded skill + one real demonstration + one structured knowledge model + one learner + one practice task + one learner attempt + one evidence-grounded feedback loop + one measurable improvement + one lineage record**

The initial domain should be selected based on actual access to an authentic practitioner and learner, not invented for the sake of the story.

## Documentation principle

This repository intentionally separates:

- **EXPLORED** — ideas, research, alternatives, competitors, hypotheses, and possibilities.
- **DECIDED** — explicit product and architecture decisions.
- **IMPLEMENTED** — code and functionality that actually exists.

This prevents exploratory work from being lost and prevents speculative AI-generated architecture from silently becoming implementation scope.
